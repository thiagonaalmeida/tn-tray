# Changelog

## 1.0.0

First public release.

- Close to tray via the window's X button, with a fully custom Win32 tray icon and context menu (Restore / Compose new message / Check for new messages / Exit).
- Silent start in tray when launched via Windows Startup (`-MapiStartup -url` flags), detected through the real process command line — manual launches always open normally.
- Native window transparency trick during boot to avoid the visible window flash, while still waiting for Thunderbird's own `delayedStartupPromise` so new-mail checking and notifications keep working correctly.
- Unread count badge on the tray icon, using Thunderbird's own `newmail.ico`.
- Click detection runs on a dedicated `ChromeWorker` thread, immune to main-thread jank during busy boot.
- Automatic recovery if `explorer.exe` restarts and the notification area is wiped out from under the extension.
- `window.focus()` interception to fix a white-flash bug when Thunderbird is reactivated externally (e.g. clicking a pinned taskbar icon) while hidden.
- Auto-start with Windows managed via the registry `Run` key, added/removed automatically on enable/disable/uninstall (with an upgrade-safe guard so a version update doesn't wrongly undo it).
- Suppresses Thunderbird's native tray icon (which only ever exposes "Exit") in favor of this extension's own, restoring the original preference values on uninstall.
- Settings page: use own tray icon, auto-start with Windows, start minimized on boot, diagnostic logging toggle.
- "Check for new messages" added to the tray menu, using Thunderbird's own `MsgGetMessagesForAllAuthenticatedAccounts()` (same as File > Get New Messages).
- Full localization (English default, Portuguese (Brazil)) for the settings page, tray menu, and unread-count tooltip, matching Thunderbird's own UI language.
- Tray menu is now anchored to the actual icon position (via `Shell_NotifyIconGetRect` + `TPM_LEFTALIGN`/`TPM_BOTTOMALIGN`) instead of only the cursor position, so it opens directly above the icon, left-aligned to it, instead of overlapping the Windows 11 hidden-icons flyout. Also trimmed to its natural width (`MNS_NOCHECK`) instead of stretching to the longest label.
- "Show log file" button in settings, next to diagnostic logging, opens the log file location directly in Explorer — no need to type `%TEMP%` manually when sending it for support.
- Pauses the background polling thread while the tray context menu is being shown, and resumes it right after. Real-world logs showed the polling thread's own `Shell_NotifyIconGetRect` calls, running concurrently with the main thread's during `TrackPopupMenu`, correlated with the menu occasionally failing to appear (~12% of right-clicks in test logs) — this removes that concurrent access window.

### Lifecycle and reliability hardening

- Invalidates the startup cache on shutdown when it isn't a full app quit (update, disable, reinstall, dev reload), so a future automatic GitHub update can't end up running stale cached code from the previous version.
- The `win.focus()` interception used to fix the reactivation white-flash is now fully undone on shutdown (restores the original `focus`, removes the `activate` listener), tracked per window instead of with a single global flag — this lays groundwork for future multi-window support, though 1.0.0 still only manages the initial main window (see Known limitations).
- The tray icon's registration (`Shell_NotifyIconW(NIM_ADD)`) now has its return value checked instead of being assumed to succeed; on the rare case it fails during boot, the window is restored instead of being left hidden with no working icon to bring it back.
- "Exit" is now handled natively, synchronously, in a single place, instead of also being routed through the background script — removes a redundant second `destroyIcon()`/quit call.
- The `resource://tntray-worker/` alias registered on startup is unregistered on shutdown, instead of staying bound to the previous version after an update.
- Recovering the tray icon after `explorer.exe` restarts no longer destroys the taskbar window icons (`WM_SETICON` handles) — only the tray-specific icon handles are recreated, so the taskbar icon doesn't risk going blank in between.
- The shared fallback icon (used only if extracting the real Thunderbird icon fails) is no longer destroyed, since it doesn't belong to the extension.
- Unread badge recalculation is now serialized: new mail, folder-change events, and the periodic timer can no longer trigger overlapping full account/folder scans at the same time.
- Startup now retries for up to ~2 seconds if the main window isn't available yet, instead of silently aborting initialization (which would leave preferences, the close-to-tray handler, and the badge never applied until the next restart).
- The diagnostic log file is capped at 5 MB and restarts instead of growing indefinitely while logging stays enabled for a long time.
- Removed unused code (an unread dictionary flag that was never read, two Win32 declarations left over from before click detection moved to the worker thread, an unused `gdi32.dll` handle) and reworded a few internal comments that read like debugging notes.
- Corrected Brazilian Portuguese text (previously missing accents throughout) and moved the translation from `_locales/pt` to `_locales/pt_BR` to be explicit about the variant. Also added the missing "Get messages" mention to the tray icon option's description in both languages.
- Removed the leftover `quit` function and its mention in the `onCommand` event description from the Experiment schema, matching the native-only "Exit" handling above.
- The early-hide timers, the `delayedStartupPromise` callback, and worker messages can no longer act after shutdown has started — closes a narrow window where an automatic update happening seconds after boot could let stale, already-scheduled callbacks run after teardown.
- Shutdown now only destroys the taskbar window icons (`WM_SETICON` handles) on a real Thunderbird quit, not on an extension update or disable, where the window is still alive and using them.
- `setAutoStart(false)` now checks the result of removing the Windows Startup registry value instead of assuming it always succeeds.
- The `win.focus()` interception now restores the exact original function reference on shutdown, instead of a re-bound copy of it.
- The early-hide retry timer is now cleared (set to `null`) before being cancelled in every path, instead of leaving a stale reference to an already-cancelled timer.
- Documented two known limitations in the README: only the initial main window is managed by the close-to-tray behavior, and Windows auto-start uses one registry entry per Windows user (multiple installs/profiles under the same user can overwrite each other's entry).
- Reworded the Thunderbird 154 compatibility statement to avoid overstating it: TN Tray has been reviewed against the 154 beta implementation, but 1.0.0 officially supports Thunderbird 152 and 153 — full 154 support is planned for the next release, after testing against a non-beta build.
- The window is now restored (not just the native tray icon) on a real disable or uninstall, not only on a version update — it no longer stays hidden and unreachable if the extension is deactivated while minimized to tray.
- `GetWindowLongPtrW`/`SetWindowLongPtrW` (used for the native transparency trick during boot) now fall back to `GetWindowLongW`/`SetWindowLongW` at runtime if the "Ptr" symbols aren't available, for correctness on 32-bit Windows.
- Startup no longer waits for the main window with a fixed retry loop; it now resolves as soon as `windows.onCreated` fires (with a 30-second safety timeout), reacting immediately instead of on the next polling interval.
- The taskbar window icon is now restored to what it was *before* TN Tray touched it (not just left as TN Tray's own icon) when shutting down for a reason other than a real app quit, completing the icon-handle lifecycle started by the previous round's fix.
- All native Win32 libraries (`user32`, `shell32`, `kernel32`, `advapi32`) are now explicitly closed on shutdown, in both Experiment APIs and the polling worker thread, instead of being left open until process exit.
- Partial Win32/registry initialization failures (a DLL opens but a required symbol doesn't exist) now clean up any libraries already opened instead of leaking handles; the polling worker's startup failures also fully terminate and reset the worker instead of leaving a half-initialized object behind.
- Removed the unused `destroy` API/schema entry (dead code since the Quit path was unified to a single native handler).
- Fixed invalid HTML (a `<div>` nested inside a `<span>`) in the settings page; the description text now uses a `<span>` with `display: block`, with no visible change.
- `init()`, `messenger.compose.beginNew()`, and every unread-badge refresh call site (new mail, folder changes, the periodic timer, and the idle-callback path) now have their promise rejections caught and logged instead of surfacing as unhandled rejections.
- Corrected the "no network requests" claim in PRIVACY.md, the README, and the FAQ to acknowledge that Thunderbird's own add-on update mechanism periodically contacts the self-hosted update manifest on GitHub Pages — the extension's own code still makes no requests, and no tracking or identifiers are added to that check.
- `destroyIcon()` no longer skips restoring/releasing the taskbar window icons when the tray icon itself never existed (e.g. registration failed at boot but the window icons were already applied) — only the tray icon's own removal step still depends on it having existed.
- The main window's previous icon is now correctly restored even when it was explicitly `NULL` (i.e. the window was using the window class's default icon, not one applied via `WM_SETICON`) — previously that case was mistaken for "nothing to restore" and TN Tray's own icon stayed stuck on the window.
- `createIcon()` now releases any icon handles it already extracted if it fails partway through (not just on a known `NIM_ADD` rejection), instead of relying solely on the next shutdown to clean them up.
- The native transparency trick used during boot now restores the window's exact previous extended style (`GWL_EXSTYLE`) instead of only clearing the two bits TN Tray itself adds, preserving any other extended style bit set by something else in the meantime.
- Added a shutdown-time safety net that restores the window if neither a real Thunderbird quit nor an update is in progress (tracked via a new `upgradeInProgress` flag) — covers cases the disable/uninstall listeners might miss, such as a development reload or a failed listener registration.
- The second, race-covering `getMainWindow()` check inside `waitForMainWindow()`, and both `load()`/`save()` calls in the settings page, now have their promise rejections caught and logged; a failed save also reverts the checkbox to its previous state.
- `setAutoStart()` failures are now logged from `background.js` instead of being silently discarded, both at startup and when the option changes.
- Updated a stray code comment that still referenced enabling diagnostics via `about:config`, from before the settings-page toggle existed.
- The temporary native transparency trick used during boot is now also undone on shutdown during an in-progress update (previously only handled for a real quit/disable/uninstall), closing the gap where a shutdown landing in the narrow window between applying and undoing it could leave the taskbar window invisible.
- `setMainWindowNativeTransparent(false)` is now a no-op unless TN Tray itself applied the transparency trick to that window, instead of always touching `WS_EX_LAYERED`/`WS_EX_TOOLWINDOW` — it no longer risks clearing extended style bits it never set on the ordinary hide/restore path (which doesn't go through the boot trick at all).
- The main window's icon-restoration bookkeeping is now updated immediately after each icon size is applied, instead of only after both sizes succeed — an exception between the two `WM_SETICON` calls no longer leaves an already-applied size unrestored at teardown.
- `createIcon()` now marks the tray icon as registered immediately after `Shell_NotifyIconW(NIM_ADD)` succeeds, and treats the follow-up `NIM_SETVERSION` call as best-effort — a failure there no longer leaves a real, visible tray icon orphaned by cleanup code that assumed nothing had been registered yet.
- Added a fail-safe for the polling worker: if it fails to start, throws during initialization, errors out asynchronously, or hits repeated exceptions in its polling loop, TN Tray now removes the tray icon (and restores the window, if it had been hidden) instead of leaving a tray icon that looks normal but no longer responds to clicks.
- "Exit" now only requests the shutdown (`Services.startup.quit`) instead of also destroying the tray icon beforehand — the request can be declined (e.g. an unsaved compose window, a blocking dialog), and the icon is now only ever torn down by `onShutdown()`, which only runs if the shutdown actually goes through.
- The close-to-tray interception no longer hijacks a real Thunderbird shutdown: it now checks `Services.startup.attemptingQuit`/`shuttingDown` and lets the window close normally in that case, instead of hiding it to the tray and inadvertently blocking the quit that was just requested.
- `forceMainWindowIcon()` no longer risks overwriting (and leaking) an already-extracted window icon handle if a previous extraction only returned one of the two sizes — it now only keeps a newly extracted handle for a size it doesn't already have, and releases the redundant one otherwise.
- Removed the `messagesRead` permission — it existed only for a `messages.onNewMailReceived` listener that never actually read any message data, just triggered a badge refresh. `folders.onFolderInfoChanged` (which only needs `accountsRead`, already granted) covers the same new-mail case.
- Corrected the FAQ's answer on whether TN Tray replaces the native tray icon — it does, by default (the README and options page already said so; the FAQ was the one place that hadn't been updated).
- Documented the extension's default settings (own tray icon, Windows auto-start, and start-minimized all on; diagnostic logging off) in the README, and added a note that disabling Windows auto-start or TN Tray in one profile can remove the shared registry entry another profile relies on.
- Tidied up a couple of `background.js` comments that read like patch notes (referencing the just-removed `onNewMailReceived` listener) instead of describing the current code.
- `forceMainWindowIcon()` now applies the large and small taskbar icon separately, each in its own try/catch with detailed diagnostic logging on failure — a real-world clean-install log showed a `ctypes.cast` exception on this path aborting the whole function (silently, since it was already caught), so neither icon size nor the restoration bookkeeping ever ran; now one size failing no longer blocks the other, and the function reports partial success instead of total failure.
- Found the actual root cause of that `ctypes.cast` exception: `WM_SETICON`'s `lParam` and return value are both an `HICON` (a handle/pointer), but the shared `SendMessageW` declaration typed them as `intptr_t`, requiring an explicit cast on every call. A dedicated `SendMessageIconW` declaration (same native symbol, `voidptr_t` typed) is now used for all four `WM_SETICON` call sites (apply and restore, both icon sizes), removing the casts entirely instead of only catching the exception they could throw.
- `launchMode.setAutoStart()` is now declared `"async": true` in its schema and implemented as an async function — Thunderbird's Experiment API docs state a function's return value only reaches the WebExtension side if it's declared async; being declared synchronous meant `messenger.launchMode.setAutoStart()` always resolved to `undefined` on the `background.js` side regardless of whether the registry write actually succeeded, producing a false "could not update Windows auto-start" console error on every boot even though the registry key was written correctly. `background.js` now awaits the call through a shared `applyAutoStart()` helper used both at startup and when the option changes.
- Fixed a real-world race between the boot-time early-hide logic and an explicit window restore: if `delayedStartupPromise` isn't found on the main window (happens on some boots), the only thing that ever hides the window is a one-shot 8-second "last resort" timer armed at boot. That timer had no idea a restore could happen before it fired, so a double-click on the tray icon (or `restoreWindow()`, used when "start minimized" is off) a few seconds after boot would show the window correctly, only for the 8-second timer to minimize it right back a moment later. A shared `idle/pending/applied/cancelled` state now tracks the boot hide across both the `delayedStartupPromise` and 8-second-timer paths; any explicit restore (tray icon double-click/menu, the `restoreWindow` API, native reactivation) cancels the pending timer and permanently no-ops the hide, instead of racing it.
- Reworded two diagnostic log lines ("janela ja existia/escondida cedo") that claimed the window was already hidden at the point they were logged — at that point it had only been made transparent, not actually minimized/hidden yet, which was misleading when reading a log to diagnose boot-timing issues.
- Replaced the custom `-trayboot` marker with the pair of native flags `-MapiStartup -url`, eliminating the "unrecognized command line flag" warning in the Thunderbird Console without changing the start-minimized behavior. Both flags are recognized and consumed by Thunderbird's own command line handler with no functional side effect (confirmed against the current source: `-MapiStartup` is only acknowledged as "this startup is due to MAPI. Don't do anything for now.", and `-url` is dropped without requiring a value) — the boot-detection logic in `launchMode` and the early-hide detection in `trayIcon` both now require this exact pair, in this order, at the end of the command line.
